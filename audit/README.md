# Аудит сайта-портфолио: как воспроизвести

Всё, что относится к аудиту, лежит в этой папке. Код сайта и проектов не менялся.
Скрипты только наблюдают: открывают живой сайт в браузере, считают и делают скриншоты.
Замеры страниц встраиваются из теста (`page.evaluate`, `add_init_script`), а не из кода сайта.

## Одна команда

Из корня репозитория:

```bash
python3 audit/run_all.py
```

Полный прогон занимает около 1,5–2 часов на слабом сервере. Больше всего времени уходит
на интро, которое сайт показывает при каждом заходе, и на 30-секундные окна наблюдения за демо.
Отдельные шаги запускаются так: `python3 audit/run_all.py --only lighthouse,a11y`.
Пропустить шаги: `--skip lighthouse`. Если хотя бы один шаг упал, код выхода равен 1.

Другой адрес сайта (например, зеркало или локальную сборку) можно задать так:
`AUDIT_BASE_URL=http://localhost:3000 python3 audit/run_all.py`.

### Что нужно установить один раз

```bash
pip install playwright && python3 -m playwright install chromium   # Chromium для всех замеров
npm install --prefix audit                                          # Lighthouse 12 и axe-core
```

Путь к Chromium задан в `scripts/common.py` (переменная `CHROME`). Lighthouse запускает тот же
браузер, которым пользуется Playwright.

## Шаги прогона

| Шаг | Скрипт | Что делает | Результат |
|---|---|---|---|
| code_scan | `scripts/code_scan.py` | Статический разбор репозитория: мёртвый и дублирующийся код, неиспользуемые файлы и зависимости, закомментированный код, секреты, README, история git. Только чтение. | `data/code_scan.json` |
| crawl | `scripts/crawl.py` | Обход внутренних страниц тремя способами: `a[href]`, клики по `role=button`, sitemap. Проверка каждой внешней ссылки. | `data/pages.json`, `links.json`, `broken_links.json` |
| hosts | `scripts/hosts_check.py` | Два адреса сайта (Vercel и vanatat.ru) по http и https, canonical/og:url каждой страницы, заголовки безопасности. | `data/hosts_check.json`, `screenshots/hosts/` |
| repos | `scripts/repos_check.py` | Публичные репозитории автора через GitHub API: описание, homepage, README, ссылки на игры. | `data/repos_check.json` |
| lighthouse | `scripts/lighthouse_runs.py` | Lighthouse, мобильный и десктопный профиль, по 3 прогона на страницу, берётся медиана. | `data/lighthouse.json` |
| page_metrics | `scripts/page_metrics.py` | 4 экрана × ключевые страницы: вёрстка, мелкий текст и мелкие кнопки, вес и запросы, ошибки консоли, SEO/OG, «тест 5 секунд». | `data/page_metrics.json`, `data/text/`, `screenshots/pages/` |
| projects | `scripts/projects_check.py` | Каждый проект: открывается ли демо, когда оно становится интерактивным, ошибки за первые 30 с, как работает на телефоне. Отдельно — публичные сборки 5 игр. | `data/projects_check.json`, `screenshots/projects/` |
| scenarios | `scripts/scenarios.py` | Сценарии S1–S5 из `inventory.md` на десктопе и телефоне, скриншот на каждом шаге. | `data/scenarios.json`, `screenshots/scenarios/` |
| explore | `scripts/explore.py` | «Потерянный посетитель» (50 случайных кликов), путь «карточка → назад», проверка единственной формы, медленная сеть в первые секунды. | `data/lost_visitor.json`, `card_roundtrip.json`, `form_check.json`, `slow_network.json`, `screenshots/lost_visitor/`, `form/`, `slow_network/` |
| a11y | `scripts/a11y.py` | axe-core (WCAG 2.1 A/AA), клавиатура, масштаб 200 %, prefers-reduced-motion. | `data/a11y.json`, `screenshots/a11y/` |
| sound | `scripts/sound_check.py` | Играет ли звук после «Пропустить» и после «без звука». | `data/sound_check.json` |
| evidence | `scripts/evidence_shots.py` | Скриншоты отдельных секций дашборда для отчётов и тексты секций для цитат. | `screenshots/sections/`, `data/sections_text.json` |
| check | `scripts/check_evidence.py` | Проверяет, что каждый файл и каждая строка кода, на которые ссылаются отчёты, существуют. | вывод в консоль, код выхода |

## Условия замеров

- **Дата:** 27.09.2026. Основной адрес — https://vanatat.vercel.app.
- **Машина:** headless-сервер Linux, Intel Pentium G4560 (2 ядра / 4 потока). Chromium из Playwright (chromium-1234).
  Процессор медленный, поэтому абсолютные цифры Lighthouse и времена хуже, чем у посетителя на современном ноутбуке.
  Сравнивать между собой страницы и режимы при этом корректно. Во время прогонов на сервере параллельно работали
  другие задачи, поэтому времена в `data/projects_check.json` и `data/scenarios.json` могут быть завышены на секунды.
- **Lighthouse 12:** стандартное троттлирование. Мобильный профиль — эмуляция Moto G Power, симулированный
  slow 4G (150 мс RTT, 1,6 Мбит/с) и замедление CPU в 4 раза. Десктоп — 1350×940, 40 мс RTT, 10 Мбит/с.
  По 3 прогона на страницу, в отчётах медиана. Lighthouse видит страницу **с интро поверх**:
  так её видит и посетитель.
- **Экраны:** 1920×1080, 1366×768, 768×1024 (тач, DPR 2), 390×844 (iPhone UA, тач, DPR 3).
- **Медленная сеть (explore.py):** 150 мс RTT, 1,6 Мбит/с вниз, 0,75 Мбит/с вверх, CPU ×4 через CDP.
- **Вежливость к живому сайту:** не больше одной навигации в секунду (`common.polite()`), нагрузочных тестов нет.
  Единственная форма на сайте — чат-симулятор «Штаба». Он ничего не отправляет на сервер: в `components/projects/StaffChatSim.tsx` нет сетевых вызовов.
- **Интро.** Сценарии проходят его так, как это сделал бы новый посетитель: «без звука», ожидание кнопки «Начать», клик.
  Технические проверки нажимают «Пропустить». Если клик пришёлся до гидратации и был проигнорирован, он повторяется
  каждые 2 с, а число проигнорированных попыток записывается.
- **Случайность:** «потерянный посетитель» использует фиксированный seed, поэтому последовательность кликов повторяема.
  Сам сайт при этом анимирован и частично случаен, так что результаты могут немного отличаться от прогона к прогону.

## Что не удалось измерить и почему

- **Lighthouse на http://vanatat.ru.** Headless Chromium под Lighthouse принудительно переводит адрес на HTTPS,
  а сертификат на vanatat.ru недействителен. В итоге получаем `NO_FCP` / `chrome-error`. Сам адрес
  в Playwright открывается (см. `data/hosts_check.json`). Lighthouse снят с https://vanatat.vercel.app: код там тот же.
- **TTI в чистом виде** (метрика Lighthouse 10+ больше не считает TTI). Вместо неё используются TBT из Lighthouse
  и собственная оценка по long tasks. На страницах сайта фоновые canvas-эффекты создают long tasks постоянно,
  поэтому «TTI» часто упирается в конец 30-секундного окна. Метод описан в `data/projects_check.json` → `method`.

## Где что лежит

- `inventory.md` — страницы, реестр проектов, сценарии, допущения.
- `reports/site.md` — сайт глазами посетителя (UX, производительность, доступность, SEO).
- `reports/projects.md` — каждый проект отдельно.
- `reports/site-as-project.md` — сайт как проект: код, репозиторий, следы генерации.
- `SUMMARY.md` — топ-10, системные проблемы, приоритеты.
- `data/` — все сырые результаты в JSON; `screenshots/` — скриншоты, на которые ссылаются отчёты.
- `scripts/check_evidence.py` — проверяет, что каждый путь к файлу, упомянутый в отчётах, существует.
