# Сайт как проект: код, репозиторий, следы генерации

Сайт — такой же экспонат портфолио, как и остальные. Технический посетитель (рекрутер,
тимлид, заказчик с разработчиком) откроет репозиторий https://github.com/Fanatat/lending2
по ссылке на профиль GitHub. Поэтому здесь описано, что он там увидит.

Основа отчёта: статический разбор `scripts/code_scan.py` → `data/code_scan.json`
(коммит `2b3eb0b`, 155 файлов в git, 106 исходников, 11 619 строк), история git,
данные консоли из `data/page_metrics.json`. Номера строк указаны по коммиту `2b3eb0b`.

Формат каждой находки: **факт** → **доказательство** → **почему вредит** → **что сделать** → **влияние / трудозатраты**.

  Виджеты проектов на отдельных страницах тоже подгружаются динамически (`components/projects/ProjectWidget.tsx:14-22`).
- **Черновые ТЗ и промпты убраны из рабочего дерева и занесены в `.gitignore`**
  (коммит `0fe9a9f` «Убрать черновые рабочие документы из публичного репозитория»).

- **Живой фид HP100 устроен честно и надёжно.** Данные идут через публичный JSON на GitHub, а устаревшие показания

## Находки

### SP-1. Каждая страница падает на гидратации: React выбрасывает серверную разметку и рисует всё заново

- **Факт.** На `/` и на 6 из 8 страниц проектов в консоли появляются ошибки React #425, #418 и #423. Это рассинхрон
  текста между сервером и браузером. Ошибка #423 означает, что React отказался от серверного HTML и перерисовал
  всё дерево на клиенте. Ошибок нет только там, где счётчика «Uptime» нет: `/en`, `/projects/friday-studio`, `/projects/content-factory`.
- **Доказательство.** `data/page_metrics.json` → `console.errors`: на `/` 4 × #425, 1 × #418, 1 × #423.
  Причина — `Date.now()` прямо при отрисовке: `components/sections/SystemStatusLine.tsx:40-41`.
  Страницы собираются статически в день сборки, а число дней «Uptime» посетитель видит в другой день, поэтому текст расходится.
  У «Пятницы» и «Контент-завода» даты нет (`lib/systemStatus.ts:31-38`, `since: null`), поэтому и ошибки нет.
- **Почему вредит.** Любой, кто откроет DevTools (а сайт сам зовёт туда пасхалкой, `lib/portfolioGuard.ts:36`),
  первым делом увидит красные ошибки. Кроме того, повторная отрисовка всего дерева удлиняет время до
  интерактивности. Клики, сделанные до её окончания, теряются: «Пропустить» в интро приходится нажимать повторно
  (`data/slow_network.json` → `clicks_ignored_before_hydration: 1`; `data/scenarios.json` → `intro.ignored_attempts`).
- **Что сделать.** Считать дни только после монтирования (`useEffect`) или рендерить счётчик только на клиенте.
  Затем открыть главную и убедиться, что консоль пуста.
- **Влияние:** высокое (доверие технического посетителя и отзывчивость первого клика). **Трудозатраты:** 1 час.

### SP-2. README описывает не тот сайт

- **Факт.** В README 36 строк. Три утверждения в нём не соответствуют коду, и в нём нет ни слова о том, как сайт сделан с ИИ.
- **Доказательство.** Строка «Framer Motion, Lenis» — но у framer-motion 0 импортов (`data/code_scan.json` →
  `npm_dependencies`, `framer-motion.unused: true`). Строка «подтягивая данные с отдельного сервера в реальном времени» —
  на деле это JSON на GitHub, обновляемый раз в 5 минут (`lib/hp100-live.ts:9-13`). Строка «минимум декоративных элементов» —
  на главной 8 canvas-слоёв, кастомный курсор, Matrix-дождь и падающие человечки (`data/page_metrics.json` → `seo.canvas_count: 8`).
  В README нет ссылки на сайт (`docs.readme_mentions` → `vercel.app: false`), нет скриншота, нет лицензии и нет рассказа о роли ИИ
  (`docs.readme_mentions_ai_process: false`).
- **Почему вредит.** Бриф прямо ставит вопрос, объясняет ли автор свой процесс с ИИ. У игр это есть (README игр упоминают
  ИИ — `data/repos_check.json` → `readme_mentions_ai: true`), а у главного экспоната нет. Расхождения README с кодом —
  типичный признак «сгенерировано и не перечитано».
- **Что сделать.** Переписать README: ссылка на сайт и скриншот; честный стек (Next 14, three.js, zustand, Lenis);
  3–5 строк о процессе (что делал ИИ, что решал автор); как устроен фид HP100.
- **Влияние:** среднее. **Трудозатраты:** 1–2 часа.

### SP-3. Статусы «Норма» и «Uptime» захардкожены, при этом в комментариях декларируется честность

- **Факт.** Семь из восьми систем всегда показывают зелёное «Норма». Флаг `online: true` задан константой, и его
  «предполагается переключать руками в день, когда система упадёт». Живой сигнал есть только у HP100.
- **Доказательство.** `lib/systemStatus.ts:31-42` (`online: true` у всех); `lib/systemStatus.ts:58-61` («the rest default to
  `online: true` and are meant to be flipped by hand the day a system actually goes down»). Рядом стоит
  `lib/systemStatus.ts:25` («Anchor dates below are real, not invented»). У «Автопилота» такие же константы:
  `components/sections/autopilot/AutopilotCard.tsx:8` (`"сегодня, автоматически"`) и `:10` (`DELIVERED_PCT = 100`).
  У All in значения — `Math.random()` (`lib/mock/portfolio.ts:61,75`).
- **Почему вредит.** Для технического посетителя это главный вопрос к портфолио «живых систем». Стоит один раз
  открыть исходник, и все зелёные индикаторы теряют вес — включая единственный настоящий, HP100.
- **Что сделать.** Там, где живого сигнала нет, убрать индикатор «Норма» и «сегодня, автоматически» либо подписать
  «статус вручную, на дату X». У All in прямо написать «значения сгенерированы для демонстрации».
- **Влияние:** высокое (доверие). **Трудозатраты:** 2–3 часа.

### SP-4. В публичной истории git остались черновики ТЗ, промпты и публичный IP сервера

- **Факт.** Файлы удалены из рабочего дерева, но остались в истории. Ветки с экспериментами висят на GitHub.
- **Доказательство.** `data/code_scan.json` → `secrets.files_deleted_but_still_in_history`: `TZ_sait_portfolio.md`,
  `ПРОМПТ_ОПИСАНИЕ_САЙТА_2026-09-03.md`, `список доработок1.txt` и ещё 15 файлов. В коммите `9fcb611` в
  `.env.local.example` и `lib/hp100-live.ts` добавлен публичный IPv4 (в отчёте замаскирован: `history_added_line_hits`).
  Комментарий в `lib/hp100-live.ts:6-8` говорит, что этот IP — прокси с одним проброшенным портом и что его «выводят из эксплуатации».
  Удалённые ветки: `origin/intro-cosmos`, `origin/worktree-lending2-portfolio-tz`, `origin/worktree-lending2-systems-fixes`, `origin/worktree-polish-round4`.
- **Почему вредит.** IP домашнего или арендованного сервера с открытым портом — лишняя поверхность атаки для автора
  проекта «Периметр» (аудит сетей). Черновые ТЗ и промпты в истории может прочитать любой, кто сделает `git log --all`.
  Решать, считается ли это «секретом», должен владелец, поэтому вопрос вынесен в SUMMARY.
- **Что сделать.** Убедиться, что порт на этом IP закрыт или адрес больше не используется. Если черновики не
  предназначены для публики — вычистить историю (`git filter-repo`) и удалить старые ветки на GitHub.
- **Влияние:** среднее (безопасность и приватность, на конверсию не влияет). **Трудозатраты:** 1 час (закрыть порт, удалить ветки) — полдня (переписать историю).
