# ТЗ: Сайт-портфолио «Лабораторный терминал»

Источники: `# Текст сайта-портфолио. Версия v7.md` (контент, финальный) + `Визуальная концепция и интерактив с.txt` (v8, визуал/анимация/интерактив). Это ТЗ — их слияние в исполнимую спецификацию. Текст ниже копируется в разметку **дословно**, без парафраз.

Исполнитель: Claude Code (Sonnet 5). Документ рассчитан на самостоятельную реализацию без дополнительных уточнений там, где это возможно; открытые вопросы вынесены в раздел 12.

---

## 0. Суть проекта

Одностраничный дашборд из 9 «систем» (реальных автономных проектов автора) + скрытая 10-я ветка + hero/closing. Тон — инженерный, антимаркетинговый: посетитель должен поверить, что перед ним живая приборная панель работающих систем, а не лендинг. Каждая карточка кликабельна и ведёт на отдельную страницу проекта (глубокое погружение — см. раздел 6, контент туда author добавит позже).

Ключевая эмоция по ТЗ: «чёрт, это же работает по-настоящему, это можно потрогать» — не декоративная красота, а ощущение работающего механизма.

## 1. Технологический стек

- **Next.js 14+ (App Router), TypeScript** — нужен нормальный роутинг на страницы проектов (`/projects/[slug]`) и SSG для скорости.
- **Tailwind CSS** — утилиты для сетки/типографики/спейсинга, дизайн-токены через CSS-переменные (раздел 3).
- **Framer Motion** — оркестрация появления блоков, page-transition «zoom-in» на карточку проекта, layout-анимации.
- **Canvas 2D (без библиотек)** — фоновый шум частиц-пыли и эффект дыма/тумана, реагирующий на курсор. Не грузить полноценный физический движок ради этого — самодельная лёгкая симуляция (репульсия частиц от курсора) достаточна и дешевле по перформансу.
- **Web Audio API** — синтез «механического» звука печати программно (осциллятор + шум, короткий клик ~10-20мс), не аудио-файл — избегаем вопросов лицензирования звука и лишнего веса.
- **Zustand** (или React Context, если стейта немного) — глобальное состояние: найденные пасхалки, режим Matrix, режим Unicorn, флаг `prefers-reduced-motion`.
- **localStorage** — персистентность найденных пасхалок между визитами.

Обоснование: визуальный документ явно требует детерминированные CSS keyframes, `IntersectionObserver`, `localStorage`, `will-change` только на hover, `transform/opacity`-анимации — это ложится на любой React-стек без тяжёлых зависимостей. Next.js даёт готовый роутинг на страницы проектов, которые в концепции прямо заложены как отдельный уровень навигации.

## 3. Дизайн-система

### Цвета (CSS custom properties)

```css
--bg-void: #0A0A0A;        /* базовый фон (в т.ч. Matrix-режим) */
--bg-panel: #101012;       /* фон карточек/панелей, чуть светлее void */
--fg-primary: #E8E8E8;     /* основной текст */
--fg-muted: #7A7A7A;       /* мета-текст, сноски */
--accent: #FFC53D;         /* тёплый жёлтый — единственный цветной акцент интерфейса */
--line: rgba(255,255,255,0.12);   /* тонкие линии/границы, 1px */
--line-glow: var(--accent);       /* свечение линии при hover */
--matrix-bg: #0A0A0A;
--matrix-fg: #00FF41;
```

Никаких теней (`box-shadow` с blur запрещён вне glow-эффектов). Разграничение — только border + контраст + свечение активных элементов (`filter: drop-shadow(0 0 6px var(--accent))` или аналог на границе, не на всём блоке).

### Типографика

- Моноширинный шрифт для ВСЕГО текста на сайте (данные, заголовки, тело): `JetBrains Mono`, фолбэк `Fira Code`, `ui-monospace`, `monospace`. Подключить через `next/font` (self-host, без внешнего CDN, чтобы не зависеть от Google Fonts аптайма).
- Заголовки блоков — крупный кегль, обычный вес (не жирный) для сохранения «технического», не рекламного тона.
- Мета-текст (сноски, «▸ Подробнее», таймкоды) — мельче, `--fg-muted`.

### Сетка и линии

- Тонкие линии 1px везде: разделители блоков, обводки карточек, таблицы.
- Hover на любой линии/границе интерактивного элемента → плавный переход к `--accent` + мягкое neon-glow (`transition: border-color .2s, filter .2s`).
- Много пустого пространства (генеральный line-height и вертикальные отступы между блоками — щедрые, не «плотный лендинг»).

## 4. Глобальные механики (на каждой странице)

### 4.1 Фоновая пыль (particle noise)
Canvas на весь вьюпорт, z-index под контентом. Частицы: 60–120 шт (адаптивно по площади экрана), едва заметные (opacity 0.05–0.15), медленный дрейф (random walk с низкой амплитудой), **не** звёздное небо — микроскопические точки, как пылинки в луче света.

### 4.2 Объёмный дым/туман, реагирующий на мышь
Отдельный canvas-слой поверх пыли, под контентом. Лёгкая симуляция: облако полупрозрачных мягких blur-пятен, которые плавно расталкиваются от курсора (репульсия по радиусу, easing-возврат в состояние покоя). Цель — ощущение, что интерфейс существует в физическом пространстве, а не плоская картинка.

**Важно:** оба слоя (4.1 и 4.2) используют случайность (`Math.random`) — это единственное место в проекте, где это разрешено. Все остальные анимации в блоках должны быть детерминированными `@keyframes`/явными transition-таймингами (прямое требование источника — «никакого Math.random() в основных движениях»).

### 4.3 Кастомный курсор
- Дефолт: обычный курсор скрыт, рисуется кастомный маркер.
- На интерактивных элементах: крестик-прицел 10×10px.
- На клике: короткая вспышка — расходящееся кольцо от точки клика, 200мс, затем исчезает.
- На мобильных/тач-устройствах — полностью отключить (нет курсора мыши).

### 4.4 Прогресс-бар скролла
Тонкая полоса (2–3px) сверху вьюпорта, цвет `--accent`, ширина = % прочитанного документа. Обновление через `scroll` listener с `requestAnimationFrame`, не через тяжёлые ре-рендеры.

### 4.5 Появление блоков при скролле
`IntersectionObserver` на каждый смысловой блок. При входе в viewport — fade+translateY(12px→0), задержка между соседними блоками/элементами внутри блока — постоянный степ 100мс (stagger), имитируя последовательную инициализацию модулей. Скролл — нативный браузерный, без кастомной инерции/smooth-scroll библиотек.

### 4.6 Переход на страницу проекта
При клике по кликабельному элементу карточки: текущий экран не исчезает мгновенно, а «разбирается»/масштабируется внутрь выбранного элемента (scale + clip-path на исходном контенте, затемнение остального экрана) → бесшовный переход на `/projects/[slug]`. Реализация — Framer Motion shared layout transition (`layoutId` на карточке, переиспользуемый на детальной странице как заголовочный блок).

### 4.7 `prefers-reduced-motion`
Полная поддержка: при включённой настройке — отключить пульсации, бегущие пакеты, параллакс дыма, purely-decorative циклы. Появление блоков — instant (без stagger/translate), функциональные переходы (переход на страницу проекта) остаются, но упрощаются до fade без 3D/масштабирования.

### 4.8 Пасхалки — общая инфраструктура
- Zustand-стор + `localStorage` ключ `foundEasterEggs`: `['matrix', 'unicorn', 'branch']`.
- Найденные пасхалки не сбрасываются между визитами.
- Секретная консольная строка при загрузке страницы (`console.log`) в духе тона сайта — намёк на то, что в консоли есть команды (не обязательный пункт, но уместен; см. открытые вопросы).

## 5. Постраничная спецификация (главный дашборд)

Для каждого блока: **Контент** (копировать as-is) → **Визуал** → **Анимация** → **Интерактив** → **Пасхалка** (если есть) → **Мобильная адаптация**.

### HERO

**Контент**
- Заголовок: «Не резюме. Список реализованных задач.»
- Строка: «Девять автономных систем. Ноль сотрудников, ноль облачных подписок, ноль обещаний. Часть из них исполняет свои функции прямо сейчас, пока вы читаете эту строку.»
- Мелкая строка снизу: «Все задачи решаются за 2000 рублей в месяц. Доказательства ниже.»

**Визуал**
Заголовок изначально невидим (`opacity:0`). Появление: плавно расширяющийся белый прямоугольник-маска движется до правой границы текста, замирает на 0.2с, затем сужается по высоте слева направо, «вскрывая» текст под собой (реализация: `clip-path` анимация двумя фазами через `@keyframes`, либо оверлей-div с width/height transition + `mix-blend-mode`).

Под заголовком — живой счётчик «9 систем работают прямо сейчас» с мигающим зелёным индикатором-точкой (CSS pulse, детерминированная). Счётчик не появляется сразу цифрой 9 — «накручивается» от 0 до 9 (числовой tween через `requestAnimationFrame` или Framer `animate()`, ~600–800мс), имитируя инициализацию.

**Анимация**
- Обе текстовые строки набираются посимвольно (typing effect), 50мс/символ, мигающий курсор `|` в конце строки во время набора и коротко после.
- Каждый «удар» символа — тихий механический клик через `lib/sound.ts` (Web Audio, не сэмпл). Звук выключаем при `prefers-reduced-motion` и по умолчанию должен быть off/on toggle не обязателен, но громкость — минимальная, ненавязчивая (обязательно дать пользователю возможность заглушить — см. открытые вопросы, п.12).
- Мелкая строка снизу появляется с задержкой 2с после основного блока — будто система «подумала».

**Пасхалка**
5 быстрых кликов по заголовку (окно ≤2с между кликами, сброс счётчика при паузе >1с между кликами) включает режим «Тёмная лаборатория» (Matrix mode): `--bg-void: #0A0A0A`, весь текст `--matrix-fg: #00FF41`, моноширинный шрифт уже есть по умолчанию. Применяется ко всей странице (глобальный класс на `<html>`/`<body>`), сохраняется в localStorage.

Чтобы намекнуть на интерактивность: при hover на заголовок курсор меняется на прицел (уже дефолт для интерактивных элементов — здесь усилить: чуть больше/другой оттенок), и текст едва заметно пульсирует (`opacity` 1↔0.92, медленно, зациклено).

**Мобильная адаптация**: та же последовательность анимаций, счётчик и заголовок в стек, typing effect сохраняется (можно сократить до 35мс/символ для экономии времени на маленьких экранах — на усмотрение реализации).

### 1. СТУДИЯ «ПЯТНИЦА»

**Контент**
- Заголовок: «Четыре игры студии «Пятница» и промо-материалы»
- Строка: «Полный цикл: от написания чистого и быстрого кода до создания промо-роликов. Пока конкурент грузит мегабайты фреймворка, наша игра уже приняла первый ход игрока.»
- ▸ Подробнее: «Отдельная система сначала разрабатывает игру, а потом ставит её в очередь на обслуживание. Готовит промо-материалы и тексты карточек для площадок. Скрипты сами поднимают игру в браузере без окна, записывают геймплей вертикально и горизонтально, проверяют, что в английскую сборку не просочилась кириллица, и монтируют ролик.»
- Карточки игр:
  - **Словоход** — «Сто уровней филворда и ни одного звукового файла в сборке: все звуки игра синтезирует сама.»
  - **Картинки по числам** — «Сто тридцать нонограмм, которые перед каждым релизом проверяют 338 автотестов.»
  - **Color Sort** — «Сортировка колб, которая проходит дальтоник наравне со всеми: сортируем по цвету и форме сразу.»
  - **Lane Battler** *(в разработке)* — «Правила боя выведены из 375 негативных отзывов на игру-лидера жанра. Мы починили ровно то, на что жалуются игроки. Вкус не имеет значения, имеют значение только факты.»

**Визуал**
4 «картриджа» (обложки игр). Десктоп: ряд с лёгким постоянным 3D-наклоном (`perspective` + `rotateY` небольшой угол, статично, не по курсору). Мобильный: вертикальный стек с щедрыми отступами.

**Анимация**
Внутри каждого картриджа — независимое слайд-шоу кадров игры, смена каждые 3с, со сдвигом по фазе между картриджами (staggered offset, например 0/750/1500/2250мс), чтобы не мигали синхронно.

Hover: картридж плавно всплывает (`translateY(-8px)`), под ним проявляется тонкая сетка-«проекция» (grid pattern, низкий opacity), в углу карточки проступает микро-текст (например «338 тестов зелёных» — вывести по одному релевантному факту на игру из уже данного текста).

**Интерактив**
Клик → анимация «вставки картриджа в слот»: экран затемняется оверлеем, картридж масштабируется и летит к центру экрана, затем — переход на страницу проекта (`/projects/friday-studio` или на страницу конкретной игры — решить на этапе роутинга, см. раздел 6).

Lane Battler (в разработке) — карточка кликабельна, но ведёт на страницу с пометкой «в разработке», без демо/видео.

**Мобильная адаптация**: 3D-наклон убрать (плоские карточки), слайд-шоу и hover-эффекты — hover заменить на tap-highlight аналог (лёгкий scale при тапе).

### 2. HP100

**Контент**
- Заголовок: «Пока ты в потоке и теряешь счет времени, плата следит за тем, чем ты дышишь»
- Строка: «CO2 и пыль невидимы, но они забирают твои HP. Нос не чувствует. Плата — чувствует. *(На самом деле плате всё равно, но мы умеем программировать).*»
- ▸ Подробнее: «Плата с семью датчиками раз в минуту отправляет на сервер температуру, влажность, давление, освещённость, летучие соединения, пыль трёх фракций и углекислый газ. Когда сервер недоступен, плата замечает это сама, копит показания в собственной памяти и досылает их с настоящими метками времени, как только связь вернулась. Один из датчиков оказался клоном с собственным протоколом: разбирали вручную, стандартные библиотеки его не видят. Схема переносится на теплицу, серверную или любое рабочее место без единой правки в логике.»

**Визуал**
Живой виджет: heatmap из вертикальных столбцов (по одному на показатель — минимум CO2, температура, влажность, пыль; остальные показатели можно свернуть в таблицу рядом). Цвет столбца — градиент от холодного синего/мятного (норма) через жёлтый к тревожному красному (критично), интерполируется по текущему значению относительно порогов.

**Анимация**
Столбцы плавно «дышат» (высота/яркость лёгкая пульсация, синхронизированная с частотой обновления данных). При CO2 > 1000 ppm — столбец CO2 переходит в тревожное, но детерминированное мигание красным (`@keyframes`, фиксированный период, не случайный).

**Интерактив**
- Клик на столбец → под ним плавно раскрывается график за 24 часа, линия рисуется слева направо как кардиограмма (ECG-style path draw, `stroke-dashoffset` анимация).
- Скролл **внутри** виджета (не страницы) — пролистывание исторических данных без ухода со страницы (`overflow-x: auto` с snap или кастомный wheel-handler на контейнере, с `event.stopPropagation` чтобы не скроллить страницу).

**Пасхалка**
DevTools (F12) → в консоли вызов `simulate('co2', 2000)` (или `window.__lab.simulate('co2', 2000)`) запускает визуальную симуляцию аварийной ситуации (столбец CO2 резко растёт, интенсивное детерминированное мигание, возможно короткое системное «уведомление» в виджете). *Техническая правка источника: буквальный ввод `/simulate co2 2000` не является валидным JS и не выполнится в консоли браузера — реализуем как вызов функции, экспонированной в `window`.*

**Мобильная адаптация**: столбцы в горизонтальный скролл-ряд вместо фиксированной ширины, график при клике раскрывается на всю ширину виджета.

### 3. АВТОПИЛОТ КАНАЛА

**Контент**
- Заголовок: «Каналы, которые публикуют и живут без меня»
- Строка: «Наполнил папку со 169 000+ фото, дальше канал через скрипт ведёт себя сам, в непредсказуемое время днём публикует посты, чтобы лента не выглядела роботом.»
- ▸ Подробнее: «Два бота. Первый раз в день выкладывает подборку из девяти фотографий с подписью и уводит использованное в архив, чтобы ничего не повторялось. Второй встаёт по расписанию: текст в 5:50, видео в 6:30, материалы собирает заранее сам из каналов-источников и раздаёт по одному в день. Второй поднят вручную и всё равно не пропустил ни одной рассылки.»

**Визуал**
Два абстрактных минималистичных «оптических сенсора» (стилизованные объективы — окружности с концентрическими кольцами, без прямых визуальных цитат из фильмов), смотрящие друг на друга. Рядом текстовый блок: дата последней публикации + счётчик «Дней без сбоев».

**Анимация**
Сенсоры плавно поворачиваются, их «взгляд» (внутренний зрачок/блик) отслеживает позицию курсора мыши на странице (не только над блоком — вся страница, с ограничением угла поворота). Периодически — «моргание» (быстрое сужение диафрагмы) или едва заметный механический сдвиг корпуса. Счётчик дней — механический одометр: перещёлкивание цифр по разрядам при обновлении значения (CSS `transform: translateY` рулонная анимация на каждый разряд).

**Интерактив**
Клик по сенсорам → переход на страницу проекта с логом работы ботов и архитектурой.

**Мобильная адаптация**: слежение за курсором заменить на слежение за наклоном устройства (`deviceorientation`) либо на фиксированный лёгкий自 цикл взгляда (простая безопасная деградация — второй вариант проще и надёжнее, рекомендуется).

### 4. МОСТ

**Контент**
- Заголовок: «Фикс для приближающегося рунета.»
- Строка: «Мост соединяет SOCKS5 с HTTP и возвращает Telegram Desktop в рабочее состояние за пару минут.»
- ▸ Подробнее: «Локальный сервер поднимается на компьютере и берёт на себя всю грязную работу: авторизацию, туннелирование, разбор соединений, с логом каждого из них. Инструкция построена как нормальная диагностика, от дешёвого к дорогому: сначала две галочки в настройках самого приложения, и только если это не помогло, запускается мост. Работает системной службой, самотест зелёный. Задача типовая: так же лечится любое приложение, которое понимает один протокол, а у вас оплачен и доступен другой.»

**Визуал**
Схема из трёх узлов: слева «Telegram Desktop», по центру «Мост», справа «HTTP-прокси». Между узлами — линии-«трубы».

**Анимация**
По трубам непрерывно бегут «пакеты» — светящиеся квадратики (`--accent`), движение вдоль пути `offset-path`/`transform` по фиксированной траектории. При успешной доставке (пришёл в конечный узел) — короткая анимация исчезновения с зелёной галочкой.

**Интерактив**
Тумблер «IPv6» рядом со схемой. Переключение в некорректное положение → мост визуально «обрывается» (труба разрывается посередине), бегущие по ней пакеты начинают падать вниз по экрану под гравитацией (простая CSS/JS парабола или `transform: translateY` с ease-in), накапливаясь «кучей» внизу вьюпорта (стопка из иконок-квадратиков, растущая с каждым новым упавшим пакетом).

**Пасхалка**
Быстрое переключение тумблера 10 раз подряд (окно, например ≤5с суммарно между переключениями) включает **Unicorn Mode**: пакеты становятся радужными (циклическая смена hue через `filter: hue-rotate` анимацию или явный набор цветов по кругу), скорость движения растёт, количество одновременных пакетов увеличивается в разы — управляемый, но визуально «хаотичный» шум.

**Мобильная адаптация**: схема вертикально (сверху вниз вместо слева направо), тумблер остаётся кликабельным элементом.

### 5. ОЛ ИН

**Контент**
- Заголовок: «Аналитика крипто-портфеля, которая видит, где рынок наказывает жадных»
- Строка: «Система видит ситуацию на рынке и ваши активы, сравнивает инструменты и показывает математику рисков. Но по устройству не способна нажать кнопку «Купить».»

Торговых сигналов она не даёт и цены не предсказывает по принципиальному решению. Все числа считает Python по специально выверенным формулам в отдельном модуле, языковая модель получает готовые цифры и пишет предложения, поэтому выдуманных чисел в отчёте не появляется. Каркас переносится на любой операционный мониторинг, где выводы формулирует ИИ.»
- Микро-сноска (мелким шрифтом, как техническая пометка): «(но что?)»

**Визуал**
Дашборд портфеля: круговая диаграмма распределения активов + таблица рисков (концентрация/просадка/ликвидность/разлоки — по одной строке на метрику). Хорошо заметная, недвусмысленная надпись: «Торговые сигналы: ОТКЛЮЧЕНЫ (Read-only)» — визуально выделена (рамка/иконка замка, но без ярких «предупреждающих» цветов вне палитры — использовать `--accent` или нейтральный `--fg-muted`+border).

**Анимация**
Цифры/значения обновляются раз в 60 секунд с микро-анимацией «flip» (переворачивание, как табло аэропорта) — реализация через `rotateX` двух слоёв (старое/новое значение) на каждый обновляемый разряд/строку.

**Интерактив**
Клик на актив (сегмент диаграммы или строка таблицы) → сегмент увеличивается (`scale`/выезд из диаграммы), переход на страницу проекта с детерминированным графиком цены и разбором логики Python-модуля.

**Пасхалка**
В консоли браузера присвоение `portfolio.readOnly = false` (объект `portfolio` экспонирован в `window` с сеттером на `readOnly`) вызывает полноэкранную красную надпись поверх интерфейса: «ДОСТУП ЗАПРЕЩЁН. Числа считает Python, не LLM.» — на 3-4с, затем плавно исчезает.

**Мобильная адаптация**: диаграмма и таблица — вертикальный стек, диаграмма уменьшенного диаметра.

### 6. КОНТЕНТ-ЗАВОД

**Контент**
- Заголовок: «Одна мысль может превратиться в целый сезон мультфильмов на трёх языках»
- Строка: «Три канала обслуживаются одним производством: сценарий, озвучка и весь материал для монтажа собираются и нумеруются для оператора, который уже волен творить.»

История пишется один раз в каноническом виде, английская, испанская и русская версии собираются из неё как производные. Двенадцать настоящих роликов уже собраны от начала до конца. Вся генерация и работа проходят на обычном домашнем компьютере, без подписок и API, в том числе и этап проверки, где LLM сама проверяет себя, что сценарий идет по плану, что персонажи на картинках не стали другими и общий антураж сохранен. И так можно параллельно вести несколько мультсериалов.»

**Анимация**

На этапе «Изображения» коробка открывается, из неё «вылетают» 12 миниатюр, парящих в воздухе (лёгкий float-эффект — синусоидальное `translateY`, у каждой миниатюры свой фазовый сдвиг). У каждого этапа — своя микро-анимация «работы механизма» (например: «Сценарий» — печатающийся текст-заглушка, «Озвучка» — пульсирующий эквалайзер-полоска, «Монтаж» — движущийся таймлайн-курсор).

**Интерактив**

**Мобильная адаптация**: горизонтальный скролл сохраняется (это её естественный формат на тач-устройствах — свайп), этапы чуть компактнее.

Иногда они любят прикалываться, но эта опция, без которой я не смог обойтись. Ни один проект здесь не заморожен: все восемь продолжают развиваться, и агенты отвечают именно за развитие. **Визуал**

Внутри круга — «зрачок» в виде мигающего терминального курсора (`_` или `>`), который смещается внутри круга, отслеживая позицию мыши на странице (ограниченная амплитуда смещения). При hover на конкретный аватар — тонкие SVG-линии связей прорисовываются к другим агентам, с которыми он «взаимодействует» (можно закрепить условные пары/группы, т.к. реальных данных о связях нет — см. открытые вопросы).

**Интерактив**
Клик по аватару → переход на страницу проекта с симулятором чата: пользователь может написать сообщение, агент отвечает заготовленной характерной фразой (набор canned-ответов на агента, минимум 3-5 вариантов, случайный выбор из набора при каждом ответе — здесь `Math.random` уместен, т.к. это не декоративная, а контентная случайность).

**Мобильная адаптация**: сетка 8 аватаров — 2 или 4 колонки вместо ряда, связи по hover заменяются на связи по tap (toggle).

### 8. ПЕРИМЕТР

Периметр закрыт.»

**Мобильная адаптация**: карта сети — упрощённая компоновка (вертикальный граф вместо широкого горизонтального), таймер пасхалки считается по времени в viewport так же.

## 7. Данные и «живые» виджеты

Два блока по v8 претендуют на «реальные» live-данные: **HP100** (сенсоры) и **ОЛ ИН** (портфель на бирже). Реальных API-ключей/эндпоинтов в этом ТЗ нет.

**Решение для этой итерации**: реализовать оба виджета на детерминированных **демо-данных** (`lib/mock-data.ts`), которые обновляются по таймеру (60с для портфеля, ~5-10с для HP100 — можно чаще для наглядности демо) и убедительно варьируются в реалистичных диапазонах (не `Math.random` в чистом виде — задать псевдо-реалистичный сценарий: плавный тренд + шум в узком коридоре).

Архитектура должна быть готова к замене на реальный источник без переписывания компонентов:
- Единый интерфейс `DataSource` (методы `subscribe`/`getLatest`/`getHistory`), с двумя реализациями: `MockDataSource` (сейчас) и заглушка `WebSocketDataSource`/`PollingDataSource` (на будущее, не реализовывать логику подключения к реальному бэкенду сейчас — только интерфейс и точку расширения).
- Обновление раз в 60с — через `polling`, WebSocket не обязателен на этом этапе (v8 допускает оба варианта: «WebSocket или polling»).

## 8. Производительность

- Все анимации — только через `transform` и `opacity` (аппаратное ускорение). Анимировать `width/height/top/left` — запрещено, кроме случаев, где это явно необходимо и обосновано (например маска заголовка в Hero — там допустимо, т.к. это одноразовая анимация при загрузке, не зацикленная).
- `will-change` — выставлять только на момент активного hover/transition, снимать после.
- Ленивая загрузка тяжёлых виджетов (heatmap HP100, конвейер Контент-завода, network map Периметра) — через `dynamic import` / загрузку по вхождению в viewport.
- Canvas-слои (пыль, дым) — ограничить частоту кадров разумным потолком (напр. `requestAnimationFrame` с троттлингом до ~30fps, если 60fps не нужен визуально), отключать/приостанавливать рендер, когда вкладка не активна (`document.visibilityState`).
- Целевые метрики: LCP < 2.5с, CLS ≈ 0, TBT в разумных пределах — несмотря на обилие анимаций, дашборд не должен ощущаться тяжёлым при первой загрузке.

## 9. Доступность (Accessibility)

- Полная поддержка `prefers-reduced-motion` (раздел 4.7) — обязательное требование, не опциональное.
- Все интерактивные элементы (карточки, тумблеры, узлы карты) — доступны с клавиатуры (`tabindex`, видимый focus-ring в `--accent`, `Enter`/`Space` эквивалентны клику).
- Alt-тексты/aria-label на декоративные vs. смысловые элементы разграничены: canvas-эффекты (`aria-hidden="true"`), контентные виджеты — с осмысленными `aria-label`.
- Кастомный курсор не должен ломать доступность: на устройствах с `pointer: coarse` или при отсутствии hover-возможности — не подключать вовсе, оставлять системный курсор/поведение.
- Цветовой контраст текста к фону — соответствует минимум WCAG AA (проверить `--fg-primary`/`--fg-muted` на `--bg-void`).

## 10. Респонсивность

Breakpoints (Tailwind по умолчанию подходит): `sm` 640, `md` 768, `lg` 1024, `xl` 1280.

- Мобильная адаптация под каждый блок расписана в разделе 5 — реализовать конкретные правила оттуда, не общий «сожмём в колонку» подход без проработки взаимодействий (сенсоры, фонарик, конвейер и т.д. требуют touch-эквивалентов).
- Кастомный курсор, hover-зависимые пасхалки (5 кликов по заголовку — работает и на тач, это клики, не hover) — явно проверить каждую пасхалку на мобильном сценарии.
